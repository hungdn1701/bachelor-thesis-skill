# Structure: research thesis

The main result answers a question through experiments or analysis. The chain that must hold: **research question → method → experiment → result → discussion → conclusion**. School rules override these chapter names.

| Part | Job | Must contain | Common failure |
|---|---|---|---|
| Introduction | Why the question matters | Problem, research questions (RQ1, RQ2…), hypotheses if any, contributions, scope, chapter outline | Contributions stated more strongly than the results allow |
| 1. Related work and gap | What is known and what is not | Work organized by idea rather than by paper, compared on stated criteria, the gap stated as a scope | "No one has studied this", with no search behind it |
| 2. Background | What the reader needs in order to follow the method | Concepts, notation and definitions used later | Theory that no later chapter uses |
| 3. Method | How the question will be answered, and why this way | Design, variables, metrics, baselines, alternatives considered, comparisons fixed before results are seen | Describing the method without justifying it |
| 4. Experimental setup | Enough detail to repeat the work | Data source and splits, hardware, software versions, parameters, seeds, number of runs, commands | Data whose origin cannot be traced |
| 5. Results and discussion | The answer to each question | Results per RQ, variation or intervals, statistical tests where claimed, negative results, comparison with prior work on the same measure, threats to validity | Interpreting one run as a general result |
| Conclusion | The answer, in brief | An answer to each RQ, limits, future work. No new claims | Stronger wording than chapter 5 |

For a group thesis, add a work division stating who did what, and make sure it matches the project history.
