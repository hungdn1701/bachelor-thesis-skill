# Gate 3: Structure

Question: are all the parts present, in order, and does each do its job?

The chapter expectations for each thesis type are in `bachelor-thesis-writing`: `references/structure-build.md` and `references/structure-research.md`. If that skill is not installed, use these minimums.

- **Build:** introduction, problem and existing systems, background, analysis and design, implementation, testing and evaluation, conclusion.
- **Research:** introduction, related work, background, method, experimental setup, results and discussion, conclusion.

A school rule overrides these names and this order.

## Checks

| Check | Finding |
|---|---|
| Required parts present and in order, per the profile | `medium` if missing; for a partial review, report only what is in scope |
| Each chapter does its job | `medium`, for example a design chapter that restates implementation, or an implementation chapter that is mostly code |
| A section with a single subsection | `medium`; each group needs at least two |
| Headings deeper than four levels | `low` |
| Stubs and unfinished text | `high` if a claimed section is empty; `[MISSING]` markers go in gate 1 |
| Every figure and table is introduced, then interpreted | `medium`; `high` if the text refers to one that does not exist |
| Numbering of figures and tables is continuous within each chapter | `medium` |
| Balance across chapters | `low` if theory takes more of the body than the student's own work |
| Abbreviations list matches usage | `low` |
| Appendices support the body and are not longer than it | `low` |
| A survey includes the original questionnaire in an appendix | `medium` |
| A group thesis has a work division | `medium` |
| Chapter openings and transitions connect to the objectives | `low` |
